Track A · Power Apps

Power Apps, step by step

Five steps. A script does all of step 2. Step 4 is the big one the first time, and a 30-minute import after that.

Think of it likea LEGO set. The script sorts every brick. The first time, your maker follows the booklet to build the model; after that, you just copy the finished model.
1

IT prepares Microsoft 365

IT admin~1 day

Making room: a separate space for Granted, an account for it to work as, and rules for outside guests.

  • A Power Platform environment called "Granted", with a data policy (checklist: docs/04 §6)
  • A service account such as svc-granted@yourcompany.com, with a licence and a mailbox
  • Guests: one-time passcodes on, MFA for guests; decide how guests are licensed (docs/05)
2

Run the set-up script

SharePoint admin20 min

One script builds the whole filing system the app keeps its records in, and locks it so only the app can use it.

# PowerShell 7 on any PC (no git? GitHub → Code → Download ZIP) > git clone https://github.com/AjaxAgents/GrantedPA > cd GrantedPA > pwsh ./setup/Setup-GrantedPA.ps1

It asks for your SharePoint name, the service account, a support email and the admin set-up code. Then it builds:

Site"Granted", guests allowed on it only
18 lists+ 2 libraries, indexes, colours
Locksowners only; secrets for the app only
Starter datacodes, settings, QR workbook, sample
Group + pageGranted Users, guest Welcome page
3

Paste two Office Scripts

as the service account15 min

Two small helpers that draw QR codes and check the admin code. Already written and tested; they just need pasting in.

  • Open QRRunner / QR-Runner.xlsx in Excel for the web → Automate → New script
  • Paste GenerateGatePassQR.ts and CheckAdminCode.ts from officescripts/, saved under those names
4

Add the app and the flows

Power Apps maker

The app is what people tap; the flows are the behind-the-scenes workers that apply the rules and send the emails.

The first time · 2–3 weeksBuild the 20 flows (powerautomate/) and the app (powerapps/) in the order in docs/06; every step and formula is written out. Then export the solution into solution/.
Every time after · 30 minutesImport the saved solution, connect it to the service account and switch the flows on:
pwsh ./setup/Import-GrantedPASolution.ps1
5

Finish, test, go live

Maker + project admin½ day
  • Create the sign-up Microsoft Form; put the app link in AppSettings and on the Welcome page
  • Share the app with Granted Users; run the scenario test in docs/07-test-plan.md
  • Ajax staff type the admin set-up code as a project code to become admins, then create the project

Track B · Azure

Azure, step by step

Five steps, and only one of them is technical: pasting one line into Azure's own command window. It builds everything below by itself.

Think of it likea flat-pack kit that builds itself. You choose where it goes and press one button; about 15 minutes later it's standing and switched on.
1

Open Azure Cloud Shell

IT · Azure Owner2 min

A command window that runs inside your web browser, already signed in to Azure. Nothing to install.

  • Go to shell.azure.com, sign in, and choose Bash
  • You need Owner on the Azure subscription (or Contributor + User Access Administrator)
2

Paste one line, press Enter

1 command
$ git clone https://github.com/AjaxAgents/Granted && bash Granted/setup/azure-setup.sh
3

Answer four questions

1 min

~15 min, automatic

Become the first admin

Project admin5 min

The admin set-up code

Ajax staff with a confirmed company email type it as a project code to become admins who can create projects.

It is not in GitHub and not in either app. You type it during set-up; the script keeps only a one-way scramble (a hash), in Key Vault (Azure) or a locked list (Power Apps).

Ask the project owner for it privately, never by group email. To change it, run the set-up again and type a new one.

Passing Granted to another team? Send them the GitHub link and this PDF. Give them the code separately, by phone or in person, or let them choose their own when they run the set-up.
